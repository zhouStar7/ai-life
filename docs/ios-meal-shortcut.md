# iOS 快捷指令记餐

快捷指令提交一句话餐食，管理员登录后在「饮食 → 快捷指令草稿」查看。打开草稿后可以修正名称、日期、餐次和份量，再点「确认入账」。提交草稿本身不会创建餐次。

## 开启入口

个人模式读取启动环境中的 `AI_LIFE_SHORTCUT_TOKEN`。生成一个随机令牌并单独保存到密码管理器。把该令牌作为启动进程的环境变量，再执行 `npm run dev`。没有配置令牌时，入口返回 404。

```sh
node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("base64url") + "\n")'
```

手机访问需要受信 HTTPS。若手机只需提交草稿，HTTPS 代理仅转发 `POST /api/shortcuts/meal-drafts` 到个人 API 的本机端口 `8787`，其他路径由代理拒绝。电脑继续用 `http://127.0.0.1:1117` 审核草稿。若同时部署手机工作台，工作台及其 API 另由代理认证保护。服务的默认绑定为回环地址。

## 在 iPhone 创建快捷指令

1. 添加「请求输入」，类型选文本，提示「吃了什么」。
2. 用「当前日期」和「格式化日期」得到 `yyyyMMddHHmmssSSS`，再附加一个八位随机数。组合结果保存为变量，作为这次提交的请求键。同一次请求重试时沿用这个变量。
3. 添加「获取 URL 内容」，URL 填 `https://你的地址/api/shortcuts/meal-drafts`，方法选 `POST`，请求体选 JSON。键 `text` 的值选第 1 步的输入。可选键 `date` 使用 `YYYY-MM-DD`，省略时使用服务器的本地日期。
4. 添加请求头 `Authorization`，值为 `Bearer ` 加令牌。添加 `Idempotency-Key`，值选第 2 步的变量。末尾可加「显示结果」。

成功响应包含草稿 `id` 和 `status`。相同请求键与内容再次提交会返回同一条草稿。同一请求键传入不同内容时返回 409。重新启动服务时移除 `AI_LIFE_SHORTCUT_TOKEN` 可关闭入口，替换令牌可让旧令牌失效。已经收到的草稿仍可在饮食页处理。

## 验收

- 从手机提交一条脱敏餐食，在电脑刷新饮食页，核对草稿只有一条。修改并确认后刷新复查餐次。
- 在同一次运行中保留请求键，重复发送相同 JSON，核对 `id` 一致。
- 替换令牌并重启服务，核对旧令牌返回 401，新令牌可发送草稿。

本机回归覆盖服务端收件、并发重试、凭据替换和 Chrome 核对入账。实机测试需要 iPhone 和可从手机访问的受信 HTTPS 地址。
